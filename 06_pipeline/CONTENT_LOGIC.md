# Content Logic · правила фабрики

> Канонический документ. Все агенты, схема NocoDB и n8n-workflows строятся **под эту логику**.
> Согласовано: 14 мая 2026.

---

## 0. Главный принцип

**Оля — единственная точка финального утверждения.** Машина не публикует ничего, что Оля не одобрила. Никакие тренды не «вставляются автоматом при score≥8» — всегда сначала alert Оле с доказательством, потом её решение.

Машина может:
- предлагать,
- готовить черновики,
- собирать доказательства,
- считать загруженность.

Машина **не может**:
- публиковать без approve,
- сдвигать карточки в плане без подтверждения Оли (при конфликте слотов),
- решать «достаточно ли релевантен тренд».

## 1. Три потока контента

### Поток A · Месячный план (скелет)

| Параметр | Значение |
|---|---|
| Источник | Editor-in-Chief агент |
| Триггер | Последний день месяца, 20:00 |
| Объём | ~180 карточек на следующий месяц (40–50/нед × 4) |
| Метка | `source = "monthly_plan"` |
| Утверждение | **Оля одна, раз в месяц, в одно касание** |
| Цвет в календаре | ⚪ Paper |
| Назначение | Базовая загрузка соцсетей даже без трендов и идей |

**Что внутри карточек на этом этапе:**
- Тема (краткая формулировка).
- Платформа, формат, дата, час.
- Пиллар (кейс/процесс/обучение/соц-доказ/продажи) — выдерживается баланс 30/25/20/15/10.
- **Текста пока нет** — Copywriter генерирует его за 24 часа до публикации.

**Что видит Оля в Plan view:**
- Календарная сетка на 4 недели вперёд.
- Цветная заливка по пилларам.
- Кнопки: «Сдвинуть», «Удалить», «Заменить тему», «Утвердить план целиком».

---

### Поток B · Тренды (реакция на рынок)

| Параметр | Значение |
|---|---|
| Источник | Trend Watcher агент |
| Триггер | Каждое утро 07:00 |
| Объём | 0–3 alert'a в день |
| Метка | `source = "trend"` |
| Утверждение | **Оля по каждому тренду, с доказательством** |
| Цвет в календаре | 🌹 Dusty Rose |

**Обязательное правило: Trend Watcher НЕ предлагает тренды без доказательств.**

Каждый alert содержит:
1. **Что за тренд** — короткое описание в одну строку.
2. **Откуда** — конкретный источник (Pinterest growth tag, TikTok hashtag, IG конкурент N).
3. **Доказательство трендовости** — минимум одно из:
   - Скриншоты 3+ публикаций топ-аккаунтов с этим элементом за последние 7 дней.
   - Цифры роста: `+340% engagement на хэштеге за неделю`.
   - Линки на конкурентов из нашего списка, которые уже выложили.
   - Аудио-трек Reels с ростом использования (для Reels-трендов).
4. **Оценка релевантности для КИТ** — score 1–10 от агента + одно предложение почему.
5. **Окно актуальности** — сколько дней тренд ещё «горячий».
6. **Конкретное предложение слота** — куда вставить, и что подвинуть/заменить.

**Что делает Оля:**
В Inbox-ленте «Тренды» видит alert с превью доказательств. Три кнопки:
- **«Делаем · вставь сейчас»** → карточка попадает в производственный пайплайн на предложенный слот.
- **«Делаем · но позже»** → Оля сама выбирает дату через picker.
- **«Не наше»** → alert уходит в архив, Trend Watcher запоминает (тренд не предлагается повторно).

Никаких автоматических вставок. Никаких score≥8 = auto.

---

### Поток C · Идеи Оли (живой голос)

| Параметр | Значение |
|---|---|
| Источник | TG-бот `@kit_ideas_bot` |
| Триггер | Оля прислала голос / текст / фото |
| Объём | Сколько даст |
| Метка | `source = "idea"` |
| Утверждение | **Оля выбирает, какие из развёрток включить** |
| Цвет в календаре | ⚫ Coal |
| Приоритет | Высший — голос Оли важнее плана |

**Поток:**
1. Оля → @kit_ideas_bot → голос 15–30 сек.
2. Whisper → текст → запись в `ideas`.
3. Idea Expander через 2–3 минуты создаёт 5–7 карточек на разные форматы.
4. Все карточки в Inbox-ленте «От тебя» со статусом `expanded`.
5. Оля проходит карточки, для каждой: **Approve / Revise / Reject**.
6. Approved карточки идут в производственный пайплайн.

**Особенность:** Idea Expander **не** предлагает все 7 форматов автоматически. Он анализирует идею:
- Если нет фото/видео — нет Reels-варианта.
- Если идея коротка (одно событие) — нет Дзен-варианта.
- Если эмоция личная — приоритет TG-формату.

## 2. Capacity Guard · защита от спама

**Правило:** в неделю не больше 50 единиц контента. Никогда.

Если поток B (тренд) или C (идея) толкает что-то в уже заполненную неделю — Editor предлагает Оле выбор:

```
┌─────────────────────────────────────────┐
│ Конфликт слотов                          │
│                                          │
│ Хочешь вставить: «Тренд "вышиванки"»     │
│ В слот: среда 18:00 IG Reels            │
│ Сейчас там: «Цитата клиента из Meze»    │
│ (плановая карточка)                      │
│                                          │
│ Что делаем с плановой?                   │
│   [ Сдвинуть на четверг ]                │
│   [ Удалить, она не критична ]           │
│   [ Оставить, тренд отменить ]           │
└─────────────────────────────────────────┘
```

Оля решает. Машина не двигает план без её разрешения.

## 3. Inbox · единое окно Оли

**Четыре ленты** в одной view, отсортированы по приоритету:

| # | Лента | Что внутри | Приоритет |
|---|---|---|---|
| 1 | **От тебя** | Карточки из её идей, ожидающие approve | Высший |
| 2 | **После событий** | Кейсы от Case Reaper после завершённых мероприятий | Высший |
| 3 | **Тренды** | Alert'ы от Trend Watcher с доказательствами | Высокий |
| 4 | **По плану** | Карточки месячного плана, готовые к approve (за 24 часа до публикации) | Средний |

Оля проходит сверху вниз. На каждой карточке три кнопки:
- **✓ Approve** → в production-очередь Publisher.
- **↻ Revise** → комментарий в `feedback`, Copywriter регенерирует, статус возвращается в очередь.
- **✕ Reject** → в архив, метрика «отказов» сохраняется для обучения Editor.

**Цель — 15 минут утром.** Если занимает больше — либо машина генерит слишком много мусора (надо настраивать промпты), либо ленты не приоритизированы (надо тюнить веса).

## 4. Утверждение месячного плана · отдельный ритуал

**Не в Inbox.** Отдельная view `Plan · [месяц]`.

Триггер: 28 числа каждого месяца, 20:00 — Editor строит план на следующий месяц.

Уведомление Оле в TG:
> 📅 План на июнь готов · 184 карточки, баланс пилларов: 31/24/20/15/10
> [Открыть в NocoDB]

**Что Оля делает (~30 минут):**
1. Смотрит календарную сетку июня.
2. Проверяет — есть ли её свадьбы / выезды в эти недели (если да — снижает нагрузку на те дни).
3. Может добавить «якорные» темы — например, серия «букеты июня».
4. Жмёт «Утвердить план».
5. Все 184 карточки переходят в статус `planned`, Copywriter генерирует тексты за 24 часа до публикации каждой.

**Если Оля игнорирует уведомление 24 часа** — Editor отправляет напоминание. Если 48 часов — план активируется автоматически (чтобы соцсети не пустели), но первая неделя помечена как «нужно проверить».

## 5. State-машина карточки

```
                  ┌──── revise ───┐
                  │               ↓
[planned] ─→ [brief] ─→ [draft_ready] ─→ [approved] ─→ [published]
                          │   │   │
                          │   │   └──→ [rejected]
                          │   │
                          │   └─→ revise → brief (loop)
                          │
                       Brand Guard fail
                          ↓
                       [brief] (regen)
```

| Статус | Что значит | Кто меняет |
|---|---|---|
| `idea` | Оля закинула идею, ждёт развёртки | Idea Expander |
| `planned` | Слот в плане, без текста | Editor |
| `brief` | Готов к производству, контекст есть | Editor / Idea Expander |
| `draft_ready` | 3 варианта текста + визуал + Brand Guard прошёл | Copywriter |
| `approved` | Оля одобрила, ждёт publish_date | Оля |
| `published` | Опубликовано, есть external_id | Publisher |
| `revise` | Оля попросила переделать | Оля |
| `rejected` | Оля отклонила | Оля |

## 6. Что из этого следует для следующих этапов

### Для NocoDB-схемы
- Таблица `ideas` — отдельная, не сливаться с `content_calendar`.
- В `content_calendar` обязательное поле `source` (enum: `monthly_plan` / `trend` / `idea` / `event`).
- В `content_calendar` поле `priority` (computed: idea/event=1, trend=2, plan=3).
- Таблица `trend_alerts` — с обязательными полями `evidence_urls`, `evidence_screenshots`, `score`, `window_days`.
- Таблица `monthly_plans` — заголовок плана + ссылка на 180 карточек, статус utверждения.

### Для агентов
- Editor строит план **до текстов** — только слоты.
- Trend Watcher должен возвращать структурированный alert с обязательным evidence.
- Idea Expander умеет **отказываться от форматов**, не всегда выдаёт 7.
- Brand Guard проверяет ВСЕ драфты до того, как они попадают в Inbox.
- Capacity Guard — не агент, а функция в Editor: проверяет перед вставкой.

### Для UI Оли
- View `Inbox` с 4 лентами.
- View `Plan · [месяц]` с календарной сеткой.
- View `Trends` с историей alert'ов и решений.
- View `Ideas` с историей её идей и тем, во что они превратились.
- View `Leads` (отдельная, из Inbox Bot).
