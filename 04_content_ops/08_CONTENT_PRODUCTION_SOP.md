## ПРОЦЕСС 1: СОЗДАНИЕ ПОСТА (стандартный)

### Шаг 1: Создание брифа (Ольга, 5 мин)

В NocoDB, таблица `content_calendar`, новая запись:
- `title` — рабочее название (например: "Свадьба Ивановых в Репино")
- `pillar` — выбрать из списка (кейс / процесс / обучение / соцдоказательство / продажи)
- `platform` — выбрать платформы
- `format` — пост / карусель / reels / stories / статья
- `publish_date` — дата и время публикации
- `hook` — первая строка (можно набросок)
- `cta` — призыв к действию
- `notes` — дополнительный контекст
- `status` — **idea**

### Шаг 2: Автоматическая генерация (n8n + Claude, 2–5 мин)

Триггер: статус записи изменён на "idea"

n8n workflow `01_content_generator.json`:
1. Получает бриф из NocoDB
2. Отправляет запрос в Claude API с системным промптом KIT
3. Claude возвращает JSON: `{text, hashtags}`
4. Запись обновляется: `body_text`, `hashtags`, статус → "done"
5. Ольга получает уведомление в Telegram

**Промпт Claude (сокращённо):**
```
Ты — контент-менеджер KIT, студии декора и флористики из СПб.
Голос: тёплый, личный, конкретный.
Пиллар: {pillar}
Платформа: {platform}
Формат: {format}
Тема: {title}
Зацепка: {hook}
CTA: {cta}
Контекст: {notes}
Верни JSON: {"text": "...", "hashtags": "..."}
```

### Шаг 3: Проверка Ольгой (10–15 мин)

Ольга открывает запись в NocoDB (или через Telegram кнопку):
- Читает сгенерированный текст
- Правит при необходимости (тон, детали, личные воспоминания)
- Загружает `media_urls` (ссылки на фото/видео)
- Меняет статус: **done** → **ready** (или возвращает в **idea** с комментарием)

### Шаг 4: Подготовка медиа (авто + ручная, 5–10 мин)

n8n workflow `05_event_content_pipeline.json`:
- Скачивает медиа
- ffmpeg конвертирует под форматы платформ
- Сохраняет в `/media/events/{event_id}/`

### Шаг 5: Публикация (авто)

n8n workflow `02_auto_publisher.json`:
- Триггер: каждый час, ищет записи с `publish_date = now` и `status = ready`
- Публикует на каждой выбранной платформе
- Обновляет статус: **published**
- При ошибке → уведомление Андрею

## ПРОЦЕСС 2: СОЗДАНИЕ КЕЙСА (после события)

### Когда запускается:
После завершения мероприятия, когда есть фото/видео от фотографа

### Чеклист после события:

**В день события (Ольга):**
- [ ] Сфотографировать детали (смартфон достаточно)
- [ ] Записать короткое видео (15–30 сек) для Stories/Reels
- [ ] Записать голосовую заметку: что было особенного, что сложно, что понравилось

**В течение 2 дней:**
- [ ] Получить от фотографа 10–15 лучших фото
- [ ] Загрузить в `/media/events/{event_name}/raw/`
- [ ] Создать запись в NocoDB `events`: тип, место, дата, статус "done", `content_ready = true`

**Автоматически (n8n):**
- [ ] Генерирует 5 типов постов (Instagram карусель, VK, Telegram, Reels, Дзен)
- [ ] Планирует публикации на 2 недели

### Что должно быть в кейсе:
- **Контекст:** тип события, место (район СПб), особый запрос клиента
- **Сложность:** что было нестандартного
- **Детали:** количество цветов, материалы, время работы
- **Реакция:** что сказали клиент/гости

## МЕДИА-БИБЛИОТЕКА: СТАНДАРТЫ

### Структура папок:
```
/media/
  /events/
    /YYYY-MM-DD-[client-name]-[type]/
      /raw/          ← оригиналы
      /instagram/    ← 1080×1350 и 1080×1080
      /vk/           ← 1280×720
      /reels/        ← 1080×1920
      /thumbnail/    ← 400×400
  /generated/        ← AI-контент
  /templates/        ← шаблоны Stories и обложек
```

### Требования к исходникам:
- Минимальное разрешение: 2000px по короткой стороне
- Формат: JPG (фото), MP4 (видео, H.264)
- Видео для Reels: минимум 30 сек, 1080×1920, 30fps
- Имя файла: `YYYY-MM-DD_[тип]_[порядковый номер].jpg`

## KPI КОНТЕНТ-ПРОИЗВОДСТВА

| Метрика | Норма | Тревожный порог |
|---------|-------|----------------|
| Публикаций/неделю | 40–50 единиц | Меньше 25 |
